Elastic{ON} Mumbai Visual Design Skill

Purpose

Use this skill whenever creating an Elastic{ON}-inspired event poster,
LinkedIn graphic, banner, thumbnail, presentation visual, landing-page
section, or social media asset.

The goal is to extract the current Elastic{ON} Mumbai design language,
not to copy the website pixel-for-pixel.

Core design formula:

Editorial typography + white space + Elastic color system +
geometric/bracket forms + controlled 3D + Mumbai identity + technical
community energy.

Prioritize, in this order:

Large editorial typography

Strong white space

Elastic brand colors

Geometric/bracket motifs

One strong visual object

Mumbai-specific imagery

Small technical metadata

Cards/panels only when useful

Use one dominant visual idea. Avoid ten competing focal points.

4. Color system

Use Elastic UI tokens where exact UI/brand colors are needed.

Accent: #BC1E70

Secondary accent: #008B87

Use a broader palette of: - White - Near-black - Elastic blue -

Recommended visual balance on white: - 55--70% white/neutral - 15--25%

combined

Do not make every accent equally strong.

Do not rely only on color to communicate meaning.

5. Typography

Primary: Inter

Use Inter for: - Hero - Headlines - Body - Labels - UI - Event
information

Suggested weights: 300, 400, 500, 600, 700, 800, with 900 only when
necessary.

Technical/monospace: Roboto Mono

Use only for: - Dates - Technical labels - Metadata - Compact
identifiers - Code-like content

Do not use Roboto Mono for all headings.

Never use decorative fonts.

Do not distort or stretch type.

Prefer: forge the future

rather than: FORGE THE FUTURE

when using the campaign phrase as editorial copy.

6. Logo rules

Use the official Elastic logo when available.

Never: - redraw it - distort it - recolor it randomly - create a fake
version - alter its proportions - place it on a low-contrast background

Always write the event correctly:

Elastic{ON}

The curly braces are an important visual motif.

7. Bracket and geometric language

Use the { } concept as a graphic language.

Allowed: - oversized curly braces - partial brackets - outlined
brackets - curved bracket forms - angular bracket forms - glossy 3D
brackets - translucent bracket objects

Use one or two major bracket forms, not dozens.

Other preferred shapes: - circles - partial circles - rounded
rectangles - diagonal planes - angular cuts - layered geometric
objects - modular blocks - abstract data structures

Avoid generic: - AI brains - cloud icons - circuit boards - random
hexagons - server racks - meaningless tech illustrations

8. 3D direction

When a premium visual object is appropriate, use one major 3D object.

Characteristics: - glossy - geometric - smooth - controlled depth -
blue/cyan dominant - subtle pink highlights - realistic but restrained
lighting - soft shadow - clean edges - premium rendering

Good objects: - 3D curly brace - abstract search/data object -
translucent blue/cyan structure - layered geometric form - abstract
AI/context object

Do not add random photorealistic objects.

9. Photography direction

Mumbai imagery should be: - cinematic - warm - premium - slightly
dreamy - recognizable - contemporary - natural

Good subjects: - Mumbai skyline - Gateway of India - Taj area -
waterfront - modern architecture - urban infrastructure - city-at-dusk

Preferred tones: - peach - soft pink - lavender - pale blue - warm
sunlight

Avoid: - neon cyberpunk Mumbai - extreme HDR - oversaturated orange -
fake futuristic cities - generic unrelated stock photos

10. Illustration direction

Mumbai line-art is encouraged for personal/community graphics.

Style: - thin black linework - white background - minimal architecture -
editorial sketch quality - selective Elastic blue/cyan accents - very
small pink/yellow highlights - clean vector-like execution

The illustration must support the typography, not overpower it.

11. Layout

Use an asymmetric editorial grid.

Preferred conceptual grid: 12 columns

Outer margin: 5--8%

Use consistent gutters and alignment anchors.

Do not center everything.

Good structure: - Logo top-left - Small eyebrow - Large event
typography - Large location - Personal identity or metadata on the
opposite side - Mumbai visual across the lower area - CTA/footer near
the bottom

White space is intentional. Never fill empty space just because it
exists.

12. Cards and panels

Cards are optional, not mandatory.

Use them for: - date - venue - profile - CTA - technical categories

Card treatment: - white/light background - thin near-black border -
small/medium radius - generous internal padding - clear hierarchy -
minimal shadow

Avoid: - card overload - excessive glassmorphism - heavy shadows -
random border colors - inconsistent radius

If information works better directly on the canvas, remove the card.

13. Borders and shadows

Borders: - 1px subtle - 1.5px editorial - 2px only for intentional
neobrutalist emphasis

Use near-black for major outlines.

Shadows: - none or extremely subtle for 2D UI - realistic soft shadows
for 3D objects

Do not turn the design into floating cards.

14. Spacing

Use an 8px base rhythm:

8 / 16 / 24 / 32 / 40 / 48 / 64 / 80 / 96 / 128

Prefer generous spacing for hero sections.

17. UX requirements

3-second test

The viewer should quickly understand: - what the event is - where it
is - who is involved

Mobile test

At small scale, these must remain readable: - Elastic{ON} - Mumbai -
person name - date

Squint test

When blurred, the hierarchy should remain: 1. Elastic{ON} 2. Mumbai 3.
Main visual 4. Metadata

Accessibility

Never rely on color alone. Maintain sufficient contrast. Never put
important text over a visually noisy background.

22. Antigravity execution workflow

Identify the asset type.

Extract only verified/user-provided content.

Establish primary, secondary, metadata, and CTA hierarchy.

Choose a visual mode:

typography + 3D

typography + Mumbai photo

typography + Mumbai line art

typography + portrait

photo + portrait

line art + portrait

Build a 12-column conceptual grid.

Start with white and black.

Add Elastic blue.

Add teal/cyan.

Add pink/yellow/red only where needed.

Add one major visual object.

Add personal identity if required.

Test at mobile scale.

Check spelling, date, venue, URL, logo, alignment, contrast, and
hierarchy.

Export at 4K where possible.

24. Final design principle

Do not produce:

"Elastic colors + random technology graphics."

Produce:

"Elastic's visual system translated into a carefully art-directed
event experience."

The strongest output combines:

Inter typography + black/white editorial space + Elastic
blue/teal/pink/yellow + bracket/geometric forms + controlled 3D
depth + Mumbai identity + technical community storytelling +
precise UI/UX hierarchy

When uncertain, remove elements instead of adding them.

The final design should feel intentional, spacious, technically
credible, visually distinctive, and human.
